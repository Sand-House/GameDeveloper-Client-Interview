# 가상함수(Virtual Function)와 가상테이블(VTable)

## 1. 가상함수란?

가상함수는 **상속 받을 클래스에서 재정의할 것으로 기대하고 정의해놓은 함수로 함수 호출 대상을 컴파일 타임이 아니라 런타임에 결정**하기 위한 C++의 메커니즘이다.  
이를 통해 부모 클래스 타입의 포인터/참조로 자식 객체를 다루면서도, **실제 객체 타입에 맞는 함수 호출(다형성)**이 가능해진다.

핵심 목적은 다음과 같다.

- 상속 관계에서 **행위의 다형성**을 제공
- 인터페이스 기반 설계 가능
- 공통 타입으로 다양한 구현을 처리

---

## 2. 가상함수가 필요한 이유

일반 멤버 함수는 호출 대상이 **포인터/참조의 타입 기준으로 결정**된다.  
이 경우 실제 객체가 자식 타입이어도 부모 함수가 호출되는 문제가 발생한다.

가상함수는 이 문제를 해결하기 위해 **객체의 실제 타입을 기준으로 함수 호출을 결정**한다.

---

## 3. 가상테이블(VTable)이란?

가상테이블은 **가상함수를 가진 클래스마다 하나씩 생성되는 함수 포인터 테이블**이다.

- 각 엔트리는 하나의 가상함수에 대응
- 실제 호출될 함수의 주소를 저장
- 클래스 단위로 공유됨

---

## 4. vptr (가상테이블 포인터)

각 객체는 내부적으로 **vptr(virtual table pointer)** 를 하나 가진다.

- vptr은 해당 객체가 사용할 **가상테이블을 가리킴**
- 객체마다 하나씩 존재
- 객체 생성 시 생성자에 의해 설정됨

즉,

- vtable: 클래스당 1개
- vptr: 객체당 1개

---

## 5. 가상함수 호출 과정

가상함수를 호출할 때의 개념적 흐름은 다음과 같다.

1. 객체에서 vptr을 읽는다
2. vptr이 가리키는 가상테이블에 접근한다
3. 호출하려는 가상함수에 해당하는 엔트리를 찾는다
4. 해당 함수 주소로 점프하여 실행한다

이 과정은 **런타임에 수행**되므로, 일반 함수 호출보다 비용이 약간 더 든다.

---

## 6. 가상테이블에 포함되는 함수

가상테이블에는 다음만 포함된다.

- virtual로 선언된 멤버 함수
- 상속받은 가상함수
- 재정의(override)된 가상함수
- virtual 소멸자

다음은 포함되지 않는다.

- 일반 멤버 함수
- static 멤버 함수
- 생성자
- 비가상 소멸자

---

## 7. 상속과 가상테이블

상속 관계에서 가상테이블은 다음과 같이 동작한다.

- 부모 클래스의 가상테이블 구조를 기준으로 슬롯이 결정됨
- 자식 클래스에서 가상함수를 override하면
  - 해당 슬롯의 함수 주소만 교체됨
- override하지 않은 가상함수는 부모의 구현을 그대로 사용

이 방식 덕분에 부모 타입 포인터로 접근해도 올바른 함수가 호출된다.

---

## 8. 생성자 / 소멸자와 가상함수

객체 생성 및 파괴 과정에서는 vptr이 단계적으로 변경된다.

- 부모 생성자 실행 중 → 부모 vtable
- 자식 생성자 실행 완료 후 → 자식 vtable
- 소멸자 호출 시에는 역순으로 변경

이 때문에 **생성자나 소멸자 내부에서 가상함수를 호출하면**,  
자식 클래스의 함수가 호출되지 않을 수 있다.

---

## 9. 성능 및 비용

가상함수 사용 시 발생하는 비용은 다음과 같다.

- 객체 크기 증가 (vptr 1개)
- 간접 호출에 따른 호출 비용
- 인라이닝 제한

따라서 가상함수는 **다형성이 필요한 경계에서만 사용하는 것이 바람직**하다.

---

## 10. 핵심 정리

- 가상함수는 런타임 다형성을 위한 기능이다
- 가상테이블은 가상함수 주소를 저장한 테이블이다
- vtable은 클래스당 1개, vptr은 객체당 1개이다
- 가상테이블에는 가상함수만 포함된다
- 가상함수 호출은 vptr → vtable → 함수 주소 순으로 이루어진다
- 가상함수의 실제 구현 방식은 컴파일러 의존적이다
