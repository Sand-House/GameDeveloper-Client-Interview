# Unreal Engine GameMode / GameState / GameInstance 정리

언리얼 엔진에서 게임의 흐름과 상태를 관리하기 위해 사용되는 핵심 클래스인  
**GameMode**, **GameState**, **GameInstance**의 역할과 차이를 정리한다.

---

## 1. GameMode

### 개요
- **게임 규칙과 로직을 정의하는 서버 전용 클래스**
- 게임의 흐름, 승패 조건, 규칙을 제어하는 핵심 역할
- **서버에서만 존재하며 클라이언트에는 생성되지 않는다**

### 특징
- Authority는 항상 서버
- 클라이언트에서 접근 불가
- 레벨마다 새로 생성됨

### 주요 역할
- 플레이어 스폰 규칙
- 게임 시작 / 종료 조건
- 승패 판정
- 게임 규칙 정의

---

## 2. GameState

### 개요
- **현재 게임의 전역 상태를 관리하는 클래스**
- GameMode가 정의한 규칙에 따라 게임의 현재 상태를 추적
- **서버와 클라이언트 간에 동기화(Replication)되는 상태 정보**를 보관

### 특징
- 서버와 모든 클라이언트에 존재
- Replication을 통해 값이 자동 동기화됨
- 레벨 전환 시 새로 생성됨

### 주로 관리하는 데이터
- 점수
- 플레이어 레벨
- 남은 시간
- 게임 종료 여부
- 모든 플레이어에게 공유되어야 하는 전역 상태

### 사용하는 이유
- 게임 상태(점수, 시간 등)를 **모든 클라이언트가 동일한 값으로 참조**하도록 하기 위함

---

## 3. GameInstance

### 개요
- **게임 전역 싱글톤 객체**
- 레벨 간 데이터를 유지하기 위한 클래스
- 게임 실행부터 종료까지 유지됨
- **서버와 클라이언트 각각의 프로세스에서 독립적으로 존재하지만 네트워크 복제나 동기화 대상이 아니기 때문에 상태 공유 X**

### 특징
- 레벨 전환 시에도 삭제되지 않음
- 서버 / 클라이언트 각각 하나씩 존재
- Replication되지 않음

### 주로 관리하는 데이터
- 진행 중인 레벨 정보
- 게임 설정 데이터
- 로그인 정보, 옵션 값 등 글로벌 데이터

---

## 4. 생명주기 비교

| 클래스        | 서버 | 클라이언트 | 레벨 전환 시 |
|--------------|------|------------|--------------|
| GameMode     | O    | X          | 재생성       |
| GameState    | O    | O          | 재생성       |
| GameInstance | O    | O          | 유지됨       |

---

## 5. 언제 무엇을 써야 하나?

- **게임 규칙 / 판정 로직** → `GameMode`
- **모든 플레이어가 공유해야 하는 상태** → `GameState`
- **레벨이 바뀌어도 유지해야 하는 데이터** → `GameInstance`
